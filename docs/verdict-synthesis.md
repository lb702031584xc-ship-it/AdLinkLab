# 判定口径统一（P2-2）

> 唯一口径：**`verdict = min(条款门禁, 盈利, 流量门)`** —— 三条腿中最弱的一条决定最终判定。
> 本文件是口径的唯一书面来源；`apps/api/src/ai/pipeline.ts` 的注释与工作表判定区的文案都指向同一口径，
> 不存在第二套口径。

## 三条腿

| 腿 | 来源 | 通过 | 未知 | 失败 |
|---|---|---|---|---|
| 条款门禁 | Terms 解析 | 条款未禁止 / 明确允许 | 无法判定（除品牌词竞价、直接链接的“未禁止 = 通过”外） | 条款明确禁止 |
| 盈利 | 代码公式（K3） | 盈利模型通过 | 关键输入缺失，无法测算 | 测算为亏 |
| 流量门 | P0-1 流量需求门 | 需求达标 | 无法查证 → **unknown，不判 fail** | 需求明显不足 |

## 规则

1. 任一腿失败 → 最终判定失败（STOP / 不建议投）。
2. 任一腿未知且无失败 → 最终判定未知/谨慎（CAUTION），必须标注“哪条腿未知 + 补什么证据”。
3. 三条腿都通过 → 才可判定通过（GO）。
4. 盈利测算只用代码公式（K3），绝不用 LLM 文本公式；流量门 unknown 绝不改写成 fail（K4）。
5. 横幅合成（工作表判定区）按条款 + 盈利 + 流量门三条合成，与本口径一致。

## 与 P1-5 / P2-6 的关系

- P1-5 测试节奏清单、P2-6 诊断码是**执行期**的节奏/诊断，不参与事前判定口径。
- P2-9 每日预警的 P0/P1/P2 分级复用同一规则源，不另设判定口径。
