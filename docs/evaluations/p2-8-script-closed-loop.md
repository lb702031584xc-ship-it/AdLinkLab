# P2-8：脚本系统闭环评估

> 状态：评估文档，不写执行代码。**不是承诺**。当前状态：手动闭环（人复制 Script、看结果、手动回填）。

## 现状（手动闭环）

1. 后端生成 Script → 用户复制到 Google Ads Scripts 运行 → 用户看日志 → 手动把结果（成功/失败/新建 ID）回填到 AdLinkLab。
2. 优点：简单、可审计、每一步都有人工确认。缺点：慢、易漏、状态不同步。

## 目标（系统闭环）

1. 后端派发任务 → Script 每 2 分钟轮询 → 执行 → 把结果/异常回传后端 → 后端更新任务状态。
2. 两个 Script 错峰运行，覆盖 Google 30 分钟单 Script 运行上限（一个跑任务、一个回传/心跳，错峰避免同时占用）。
3. 版本检查：v3 及以下强制升级；v4/v5 可用（版本由 Script 上报，后端校验）。
4. 约 2 分钟异步延迟需在 UI 明确标注（“结果约 2 分钟后回传”，不是实时）。

## 评估维度

| 维度 | 要求 |
|---|---|
| 派发通道 | 任务需签名 + 防重放（nonce + 过期时间）；Script 只认本租户的任务 |
| 回传通道 | 结果需校验（签名 + 任务 ID 匹配）；防伪造（非本租户 Script 的回传拒绝） |
| 错峰调度 | 两个 Script 错峰 1 分钟，避免同时触发 Google 限流 |
| 版本管理 | v3 及以下强制升级；v4/v5 可用；未知版本拒绝并提示升级 |
| 重试 / DLQ | 回传失败重试 3 次，仍失败进 DLQ（P1-21），人工在 /jobs 页处理 |
| 租户隔离 | 任务、结果、日志全部按 tenantId 隔离，跨租户任务绝不互相可见 |
| 审计 | 派发、执行、回传、重试、失败全部写 AuditLog |
| 成本 / 风险 | 轮询增加 Script 运行次数（Google 限额内）；回传通道被伪造会导致假状态，必须签名 |

## 分阶段落地（建议）

1. **阶段 1（现状）**：手动闭环 + 手动回填；先把手动回填的表单做顺。
2. **阶段 2（试点）**：轮询 + 回传，只覆盖一种任务类型（如换链接），单租户试点。
3. **阶段 3（扩展）**：试点通过后，再扩展到其他任务类型。

## 不做

- 不做 Script 自动静默执行高危操作（删系列、改预算、提预算）；高危操作永远需要人工确认。
- 不做跨租户任务共享；不做 Script 直连数据库。
