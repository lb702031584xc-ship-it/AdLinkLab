# P1-13：直连 Google Ads API — 阶段一演练评估

> 状态：评估文档，不直接实现。直连 API 目前**默认关闭**；任何写入操作都需要另行提案 + 管理员授权 + 明确的演练记录。

## 结论先行

- 阶段一（本评估覆盖）：只做 **Script-first + `validateOnly` 干跑** + 前后审计对比。**不写任何真实广告实体**，不改预算、不改出价、不碰现有系列。
- 阶段二（未来，另行提案）：仅限 tCPA / tROAS / 否词 / 排期四类写入；同样默认关闭，需逐项授权。
- 教学视频里“API 与 Script 完全一样”的说法**未经核实**：两者在配额、报错、幂等、审计链路上并不相同，本评估不采信该说法。

## 阶段一演练设计

1. **Script-first**：现有 Script 渠道保持主链路；直连 API 只做只读查询 + `validateOnly` 干跑，不参与生产写路径。
2. **干跑（`validateOnly: true` 默认）**：对同一计划分别走 Script 与 API 干跑，对比返回的校验结果（字段、预算、出价、排期、否词），差异记入审计。
3. **前后审计**：演练前写 `DIRECT_API_DRY_RUN_BEFORE`（计划快照），演练后写 `DIRECT_API_DRY_RUN_AFTER`（双方返回 + 差异清单），与 P1-16 的 BEFORE/AFTER 同一审计口径。
4. **默认 PAUSED**：即使未来进入阶段二，新建系列一律 PAUSED，人工审核后开启（与 Script 渠道一致）。

## 申请难度（诚实说明）

- 需要：MCC ID + GCP 凭据 + Developer Token（初始为 TEST 级别，TEST 只能操作测试账号）。
- 申请与审核周期不确定；Explorer 配额约 2000+/天（约 10 条广告量级），正式配额需另行申请。
- 在拿到正式 Developer Token 并通过阶段一演练之前，**不承诺任何直连写入时间表**。

## 风险与刹车

- 直连写入一旦出错，影响面是整个 MCC；Script 渠道的错误只影响单个 Script 运行。
- 任何直连写入必须走 §5 管理员授权（申请 → 审批 → 白名单 → 上限 → 自动过期 → 审计），且必须有回滚方案（P1-16 审计 + 人工逆向清单）。
- 演练期间发现任何未预期的写入行为 → 立即停用直连路径，恢复纯 Script 链路。
